# 配料表风险扫描 · Ingredient Risk Scanner

> 用手机拍照识别**食品配料表 / 护肤品成分表 / 化妆品成分表**，自动匹配已知的「对身体可能有风险的成分」并标注风险等级与风险类型。
> 数据来源以央视新闻、各地市场监管抽检通报、WHO/IARC、国家药监局、《化妆品安全技术规范》、**GB 2760-2024** 等公开报道与规范为依据。

这是一个**纯静态 PWA（渐进式 Web 应用）**，无后端、无服务器，全部在手机/电脑浏览器内本地运行（OCR 也在浏览器内完成）。可「添加到主屏幕」像 App 一样离线使用。

---

## ✨ 功能

- 📷 **拍照识别**：调用摄像头，通过浏览器端 OCR（Tesseract.js，支持中文 `chi_sim` + 英文 `eng`）提取配料表文字。
- 🏷️ **自动分类与命名**：识别后自动归类（食品 / 护肤品 / 化妆品 / 食品接触），并尝试从文字中推断产品名称。
- ⚠️ **风险标注**：逐条匹配内置风险库（60 项），命中即展示「风险等级 + 风险标识」。
- 🗂️ **记录归档**：每次扫描自动保存，按分类展示，可随时回看、删除。
- 🔄 **远程可更新风险库**：风险库以 JSON 形式托管，联网时自动拉取最新版本，离线则回退到内置库（无需改代码即可更新数据库）。
- ☁️ **多端同步（Supabase）**：开启后，扫描记录可在手机与电脑之间实时同步（详见下文「多端同步」）。
- 📱 **PWA 离线**：支持「添加到主屏幕」与离线打开。

## 🚀 使用方式

### 方式一：直接用（已部署）
打开部署好的站点（GitHub Pages），允许摄像头权限，对准配料表拍照即可。

> ⚠️ 摄像头 API 要求 **HTTPS 或 localhost**。请通过 `https://` 链接打开；不要直接双击本地 `index.html`（会被 `file://` 协议拦截摄像头）。

### 方式二：本地运行
任意目录即可，建议**避免 `cd` 进中文路径目录**以防乱码。

```bash
# 1) 进入项目根目录
cd /path/to/ingredient-risk-scanner

# 2) 启动一个静态服务器（任选其一）
python3 -m http.server 8080
# 或
npx http-server -p 8080

# 3) 浏览器打开
#    http://localhost:8080
```

### 安装为 App
- **手机（iOS Safari）**：分享 → 添加到主屏幕。
- **手机（Android Chrome）**：右上菜单 → 安装应用 / 添加到主屏幕。
- **桌面（Chrome/Edge）**：地址栏右侧「安装」图标。

## 🧠 风险标识体系

为了一目了然，每种风险用一个 Emoji 标识 + 一个风险等级（🔴高 / 🟠中 / 🟡低）表示：

| 标识 | 含义 | 标识 | 含义 |
|------|------|------|------|
| 🚫 非法添加 | 法律/规范明令禁止添加的物质 | ☢️ 致癌风险 | IARC 等权威机构提示的致癌/可疑致癌物 |
| 💉 激素干扰 | 干扰内分泌的环境激素 / 激素类物质 | ⚠️ 重金属 | 铅、汞、砷等重金属污染 |
| 🫀 代谢负担 | 加重代谢系统负担（如添加糖、反式脂肪） | 🎨 人工色素 | 合成着色剂 |
| 🍬 甜味剂 | 人工/高倍甜味剂 | 🧪 防腐风险 | 防腐剂（含甲醛释放体等高风险防腐） |
| 🔥 刺激致敏 | 易致刺激、过敏的成分 | | |

**风险等级说明**
- 🔴 高：非法添加、禁用原料、明确一类致癌物等，应尽量避免。
- 🟠 中：限用添加剂、加工产物、潜在内分泌干扰或致敏成分，注意摄入/使用频次与人群（如孕妇、儿童）。
- 🟡 低：法规限量内广泛认为安全，但部分人可能敏感（如香精、酒精），敏感肌留意。

> 本工具仅作**风险提醒与科普参考**，不能替代专业检测、医生或监管部门的判定。如有健康疑虑请咨询专业人士。

## 🔄 远程可更新风险库

风险库由单一数据源 `js/db.js` + `js/risk-tags.js` 生成，构建（或手动运行脚本）后输出为：

- `data/ingredients.json` — 60 项成分
- `data/risk-tags.json` — 风险标识定义与映射
- `data/db-version.json` — 版本号 / 更新日期 / 数量

App 启动时**优先联网拉取**最新的 `data/*.json`；若离线或拉取失败，则回退到内置 `window.RISK_DB`。
这样更新风险库只需改 `js/db.js` 并重新生成 JSON / 推送，无需改动前端逻辑。

```bash
# 改完 js/db.js / js/risk-tags.js 后，重新生成 data/*.json
node scripts/build-data.js
```

## ☁️ 多端同步（Supabase）

扫描记录可跨设备同步。本项目已内置连接到你的 Supabase 项目，开启后：

1. 首次开启同步会**自动生成一串随机「同步空间 ID」**（形如 `irs_xxxx`），并保存在本机 `localStorage`。
2. 在**另一台设备**上用**相同的「同步空间 ID」**开启同步，即可共享同一批记录。
3. 冲突按 `updated_at` 取较新版本（后写覆盖）；删除通过「墓碑」标记同步，确保删除也能跨设备传播。

### 首次使用：在 Supabase 建表（只需一次）

你的 Supabase 项目：`https://rbmxgcholrcwjyzwnqmv.supabase.co`

进入该项目的 **SQL Editor**，粘贴执行以下 SQL（App 内「关于 / 同步设置」里也有同样的文本可一键复制）：

```sql
-- 在你的 Supabase 项目 SQL Editor 执行一次：
create table if not exists public.scan_records (
  id text primary key,
  space_key text not null,
  data jsonb not null,
  updated_at timestamptz not null default now()
);
create index if not exists scan_records_space_idx on public.scan_records (space_key);
alter table public.scan_records enable row level security;
drop policy if exists "anon_scan_all" on public.scan_records;
create policy "anon_scan_all" on public.scan_records for all to anon using (true) with check (true);
```

> 该策略开放给 anon（与前端公开 key 一致），适合个人自用 / 非敏感记录。若用于更私密场景，建议改用 Supabase Auth 登录后按 `auth.uid()` 限定行权限。

执行完 SQL、并把「同步空间 ID」在手机与电脑都填成同一个，即可开始同步。

## 🛠 部署（GitHub Pages + GitHub Actions）

仓库已配置 **GitHub Actions 自动部署**：`push` 到 `main` 即自动构建风险库 JSON 并发布到 GitHub Pages。

工作流文件：`.github/workflows/deploy.yml`

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: node scripts/build-data.js   # 生成 data/*.json
      - uses: actions/upload-pages-artifact@v3
        with: { path: '.' }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Pages 来源需设置为 **GitHub Actions**（而非 branch）。若仍在用 branch 部署，可在仓库
`Settings → Pages → Build and deployment → Source` 改为 `GitHub Actions`，或用仓库管理员 token 调用
`PUT /repos/<owner>/<repo>/pages` 设置 `{"build_type":"workflow","source":{"branch":"main","path":"/"}}`。
